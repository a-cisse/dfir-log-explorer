# UI/UX redesign audit and migration

## Baseline

Audited accepted MVP 0 (`origin/main`, `82d941f`) before editing. The canonical working tree was clean, and no other development process was active. Work uses `codex/ui-ux-refonte`.

- React 19, TypeScript, Vite, Tauri 2; locally bundled Inter and Lucide icons.
- TanStack Table and Virtual provide a bounded, virtualized event page (500 rows).
- Rust `log-core` owns buffered, read-only ingestion, SHA-256, source stability checks, cancellation and transactional rollback. DuckDB stores original bytes, display text, line numbers, byte offsets and Apache fields in a temporary local session.
- Native Tauri commands select and import one local file, query pages, inspect full events and cancel imports. Browser mode is a labeled synthetic fixture generated by the production engine.
- Built-in formats: auto recognition, Apache Common/Combined access logs, plain text. No Apache Error parser, cases, multiple sources, saved searches, export or custom parser editor exists.
- Search is a bound, case-insensitive literal raw-text substring; an independent warning filter exists. Original source order and timezone offsets are preserved. Failed Apache validation currently discards all structured fields even when most were recoverable.
- Sessions and theme settings are not persisted. Normal exit drops the temporary database. Line size is capped at 1 MiB. Binary/compressed/UTF-16 sources are rejected explicitly.
- Existing validation: Rust parser/ingestion/security tests, Vitest bridge boundary test, Playwright explorer/cancellation/literal-search tests, TypeScript production build, Prettier, rustfmt, Clippy, platform CI and synthetic benchmark.

## Decisions and sequence

1. Retain frameworks, dependencies, native import boundaries, transaction semantics, byte preservation and session lifecycle.
2. Adapt existing Apache validation to retain valid fields and report mutually exclusive Parsed/Partial/Unparsed. Missing optional Common/Combined fields remain valid. Plain text mode is a successful raw-text reader; unrecognized auto lines remain Unparsed without an invented warning.
3. Add backward-compatible optional query criteria, whitelisted server sorting and bounded aggregate/timeline responses. Avoid page-local totals and client-side sorting of partial datasets.
4. Replace green decorative styling with centralized slate/blue light and dark tokens, persistent Light/Dark/System preferences, a compact collapsible sidebar and source-centered workspace.
5. Refactor the explorer, parsing summary, timeline, column controls and tabbed inspector. Implement only available navigation (Explore, Evidence, Parsers, Settings).
6. Verify retained behavior and new parsing/filtering/statistics interactions using real engine fixtures, browser tests and a large synthetic benchmark. Record platform and performance limitations explicitly.

No new dependencies or parser formats are planned. No service changes, deployments, merges or original-source mutations are part of this task.
